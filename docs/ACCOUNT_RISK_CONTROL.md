# 账户访问与风控

## 访问边界

以下为匿名登录默认关闭时的访问边界，管理员可在「系统设置 → 身份登录」开启「允许匿名登录」

- 首页与公开房间列表及歌曲封面允许未登录只读浏览，房间详情、加入或创建房间、随机匹配、电视投屏、点歌、歌词、媒体代理和汽水播放凭证均要求已登录的 OpenMusic 账户
- 未登录公开列表按 IP 每分钟最多 60 次，复用大厅封面解析与缓存，返回大厅可见摘要和封面，不返回成员身份、密码或房间凭据，Redis 不可用时拒绝列表请求
- 公开封面仅允许 `GET /api/meting` 的 `type=pic`，音源、ID、尺寸与参数白名单均校验，最大尺寸 2048，按可信 IP 每分钟最多 240 次，返回内容必须为白名单图片类型，继续执行 SSRF、大小、超时和重定向校验
- 封面请求可附带有效账户以记录按 IP 的图片次数，不要求账户或稳定房间身份，不消耗歌曲与账户业务额度，也不产生歌曲 IP 切换、访问 IP 或客户端特征加分，匿名封面仅执行 IP 限流
- HTTP 校验服务端 Ed25519 签名的账户访问令牌、Redis 会话族、稳定房间身份、请求来源与访问额度，Socket 在握手及每次事件时重新校验账户
- 仅登录与注册、第三方授权回调、登录状态、安装引导、健康检查和必要静态信息允许未登录访问，`/wx-proxy` 与 `/cgi-bin` 微信代理同样要求账户登录，不能仅凭旧设备凭据使用
- 微信允许未登录首次扫码，但只开放专用的 `/api/auth/wechat/start`、`/qr`、`/poll`、`/account` 登录链路，不开放通用代理或音乐业务
- 未登录的 bootstrap 只建立登录流程需要的 HttpOnly 设备身份，不返回业务 clientId、API 签名密钥或音源能力，也不能据此调用业务接口
- 登录后 bootstrap 同样不再返回 `apiSignKey`，网页不能取得登录私钥、共享 HMAC key 或 Meting API Token
- GitHub 与 Linux Do 的普通账户登录、绑定、后台登录、后台绑定及旧房主绑定、找回统一将 OAuth state 绑定到发起浏览器的 HttpOnly 随机挑战，在交换授权码前由 Redis 原子单次消费，跨浏览器回调、重复回调和存储故障均不能完成授权
- 挑战最长保留 10 分钟，部署此修复前发起且未绑定浏览器的旧授权跳转不再接受，用户需重新发起授权，管理员密码登录不受影响，无需迁移或清除已有账户、绑定关系和会话

### 可选匿名登录

- `anonymousLoginEnabled` 仅通过后台运行配置维护，默认 `false`，未登录会话响应追加 `anonymousAllowed`，不将游客标记为真实账户
- 开启后使用服务端签名的 HttpOnly 设备身份，bootstrap 返回游客 `clientId` 与公开音源能力，房间操作和收藏继续走既有权限校验及 Redis 链路
- 从游客 userId 派生稳定的 `acct_anon_` 风控主体，HTTP 与 Socket 仍执行请求额度、封禁、风控记录和异常访问验证，账户专属接口与管理员认证不开放给游客
- 已归属账户的设备身份不能直接降级为游客读取该账户数据，无有效账户会话时 bootstrap 会建立新的游客身份，存储校验失败时拒绝访问
- 关闭后后续匿名 HTTP 业务请求立即拒绝，Socket 下一次事件或最长 30 秒的周期校验时断开，未修改现有账户令牌、Redis 键格式或移动端桥接命令

## 邮箱注册限制

- 申请注册验证码与提交邮箱注册共用服务端域名白名单，非白名单地址返回 HTTP 400 和 `EMAIL_DOMAIN_NOT_ALLOWED`，在访问账户存储、生成验证码、发送邮件和计算密码哈希之前拒绝
- 精确匹配规范化后的邮箱域名，支持首尾空格和大小写规范化，不接受子域名、相似后缀、自定义域名、企业邮箱或未列入名单的临时邮箱域名
- 当前支持：`qq.com`、`foxmail.com`、`163.com`、`126.com`、`yeah.net`、`sina.com`、`sina.cn`、`sohu.com`、`139.com`、`189.cn`、`wo.cn`、`gmail.com`、`outlook.com`、`hotmail.com`、`live.com`、`msn.com`、`icloud.com`、`me.com`、`mac.com`、`yahoo.com`、`aol.com`、`proton.me`、`protonmail.com`
- 只限制新的邮箱注册，不清理已有账户，不改变原邮箱密码登录、第三方登录或微信首登，升级前已发出的非白名单邮箱验证码不再能用于注册
- 白名单不是实名验证或反批量注册保证，公共邮箱仍需验证邮箱验证码，并继续受现有 IP、邮箱发送频率与账户访问风控限制
- 此规则随服务端版本发布，无新增环境变量或 Redis 数据迁移，发布后更新客户端资源即可显示说明，回滚服务端版本会恢复旧注册策略

## 非对称登录与无感续期

### 旧游客升级与缓存迁移

- 升级不清理本站 Cookie、localStorage、sessionStorage 或 IndexedDB，先更新网页资源并登录账户，未登录仍不能使用业务接口
- 原游客签名身份仍有效时沿用原身份，签名身份已过期但 HttpOnly 设备 Cookie 仍存在时，登录阶段从 Redis 权威设备绑定恢复原身份，不依赖旧网页先执行 bootstrap
- 已验证且未归属其他账户的游客身份可保留或迁移 Redis 收藏及房间归属，已归属其他账户的身份不可随切换账户迁入，设备绑定读取或持久化失败时不静默创建替代身份或宣称迁移成功
- 仅有本地收藏缓存而没有有效身份凭据时，登录后将缓存歌曲与分类作为普通导入内容写入当前账户 Redis，不接受缓存中的 userId、clientId、deviceId 或房间 ID 来认领任何服务端资源
- 缓存导入不要求旧游客 handoff Cookie，handoff 只说明已验证的来源关系，不授予读取其他游客数据的权限，导入接口仍受账户登录、来源校验、稳定身份和额度保护
- 旧歌曲与分类一并分批迁移，只有分类的缓存也会实际请求服务端，若歌曲中的旧分类缺少独立分类缓存则从歌曲元数据补齐
- 容量不足、分类未完整保存、网络失败、缓存被另一标签页修改或账户切换时，保留原缓存供重试，所有批次确认成功且本地快照未变化后才删除游客缓存，收藏权威始终是 Redis
- 新网页每批迁移附带预期账户 ID 作为一致性检查，服务端仍以账户会话裁决权限，切换账户后拒绝旧迁移请求，旧客户端不带此字段时仍按当前登录账户安全导入
- Cookie、设备绑定均已丢失时，不能只凭前端缓存安全恢复服务端私有房间或 Redis 收藏，需使用原绑定身份或由管理员核实处理，本地仍保留的收藏内容可以导入

### 微信文件传输助手首登

- 复用文件传输助手 UIN，不是公众号或开放平台 OAuth openid，也不需要配置这些平台的 app secret
- 服务端向固定微信 HTTPS 地址申请二维码 UUID、取二维码、轮询确认，再兑换官方票据并调用 `webwxinit`，初始化成功且 UIN 一致才登录或绑定
- 浏览器仅取得同源二维码图片与扫码状态，不取得微信 UUID、UIN、sid、skey、pass_ticket，也不能提交 UIN、openid、重定向地址来冒充身份
- 验证的是服务端收到的微信 HTTPS 响应，不把浏览器 User-Agent、Origin、Referer 或自报来源当作微信身份凭据
- 登录挑战使用 5 分钟 HttpOnly、SameSite=Strict Cookie，Redis 只保存挑战与验证后的 UIN，不持久化微信会话密钥，账户与会话写入成功后原子单次消费
- 完成登录或绑定使用 Redis 独占锁，下游短暂失败保留扫码确认状态，重复提交不能并发消费；轮询拿到锁后重新读取状态，避免旧快照误判为失效
- 客户端对临时网络、服务不可用和处理中响应最多重试 3 次，延迟 1、2、4 秒，过期、拒绝和官方身份校验不通过仍需重新扫码，关闭弹窗取消客户端重试
- 申请按 IP 限流，二维码与轮询按会话限流，官方请求限时、限大小、重定向严格限制主机与路径，不使用任意微信代理兜底
- 微信绑定同样走服务端扫码链路，但完成绑定必须先有可用的本站账户，原 `wechat` UIN 身份索引保持不变
- 文件传输助手协议并非本项目可保证稳定的公开 OAuth 契约，真实扫码与官方响应兼容性仍需上线前验收，若缺失身份字段或出现新主机则拒绝登录，不能为兼容而关闭校验

### 账户令牌

- 服务端使用站点级 Ed25519 公私钥签发账户访问 JWT，固定 `alg=EdDSA`、issuer、audience 和 key id，签名绑定账户与会话族，不能把其他类型令牌当登录凭证
- 公钥用于服务端验签，私钥仅在服务端内存使用，并通过既有凭证加密能力加密后保存在 Redis 的 `openmusic:account:auth:v2:signing-key`，不通过任何前端接口返回
- 现有凭证加密主密钥、`CLIENT_ID_SECRET`、运行时配置与 Redis 必须稳定持久并备份，不能在重启时轮换，签名密钥已存在但无法解密时拒绝登录，不覆盖旧值，密钥及其初始化标记均须保留，已初始化后仅丢失私钥记录时禁止重新生成
- 访问令牌固定有效 3 天，普通请求与会话查询不滑动延长期限，原 `ACCOUNT_SESSION_TTL_SEC` 环境变量不再覆盖此安全边界
- refresh token 使用独立随机秘密，有效期为首次登录起 30 天，续期不会延长此绝对期限，最后一次签发的访问令牌也不能超出该期限，超过后需要重新登录
- 访问与刷新凭证只通过 HttpOnly Cookie 设置，不放入 JSON、URL、localStorage、sessionStorage 或移动端桥接，生产默认 Secure，刷新 Cookie 使用 `Path=/api/auth` 与 `SameSite=Strict`
- 前端在剩余 15 分钟内通过 `POST /api/auth/refresh` 无感续期，前台每分钟、窗口恢复焦点及业务调用时检查，访问令牌已经过期但 refresh 有效时仍可恢复
- 业务 401 只尝试一次刷新与重试，不对登录错误、风控拒绝或外链进行刷新，不重放已经执行成功的业务操作
- 刷新使用 Redis Lua 原子轮换，同一旧凭证 10 秒内返回同一组新凭证，以兼容多标签页与网络重试，宽限后重复使用已消费凭证会撤销整个会话族并记录安全事件
- 当前 refresh 仅以哈希保存，宽限期返回结果加密保存 10 秒，已消费凭证使用有界的会话族哈希保存到绝对过期，单会话族最多轮换 4096 次，异常耗尽后撤销并要求重登，注销或重放撤销会清理该族刷新历史，不使用进程内会话兜底
- 刷新受账户与 IP 配额控制，人工限制不销毁登录态，也不授予其他业务权限，单进程还限制同 IP 每分钟最多 60 次刷新尝试，成功刷新同步通知其他标签页更新 Socket 握手，不增加桥接字段
- 注销撤销会话族，旧访问与刷新令牌都不可再用，Redis 故障时返回失败供重试，不把仅清除浏览器 Cookie 描述为已完成服务端注销

浏览器原先使用可见共享 key 生成的 `X-OM-*` 和 `om_sign` 不再作为业务授权来源，替换为服务端私钥签名的账户令牌与 Redis 撤销校验，不保留旧匿名或旧账户随机令牌的兼容入口

登录、注册、刷新、退出与业务写操作均校验 Origin / Fetch Metadata，无 Origin 的程序化写请求必须携带固定的 `X-OpenMusic-Request: 1` 非凭证请求头，跨站不可信 Origin 即使带该头仍拒绝，管理后台和安装继续使用自己的独立来源校验

OAuth 的 start 与 callback 顶层 GET 导航允许第三方站点跳转，但继续严格执行既有 OAuth state、用途、会话与回调校验，不开放业务 API 的跨站例外

Socket 在 Engine.IO 的 `allowRequest` 入口验证 Origin，而不只依赖 HTTP CORS，拒绝非本站且未列入允许来源的 WebSocket 握手，缺少 Origin 的原生客户端仍必须通过账户令牌与 Redis 校验

空闲 Socket 同样受账户约束，访问令牌到期即由服务端断开，每 30 秒复核撤销与风险处置，单次复核最多等待 5 秒，跨进程处置存在这一检测窗口，不描述为即时撤销，断连会释放监视器与会话索引

网页收到访问到期通知后先尝试静默续期并恢复原房间，仅确认无法恢复登录态时提示登录，短暂网络失败保留房间并按既有重连策略重试

早于账户令牌体系且无法验证的历史会话需重新认证，旧签名媒体 URL 不能绕过新账户门禁，历史会话 Redis 键不自动删除，以免破坏备份与配套回滚；当前 v2 令牌中未绑定设备的有效会话按下文设备兼容规则恢复，不因设备证明升级强制重新登录
- HTTP 账户缺失返回 `401 ACCOUNT_AUTH_REQUIRED`，身份不一致返回 `401 ACCOUNT_IDENTITY_MISMATCH`，人工限制的普通业务返回 `403 ACCOUNT_RISK_BLOCKED`，音乐 URL 替代策略见下文
- 配额不足返回 `429 ACCOUNT_RATE_LIMITED` 与 `Retry-After`，每日额度耗尽时等待至下一个北京时间自然日
- Redis 或账户验证不可用返回 503，不提供内存权威数据或匿名降级
- 业务 API 和代理媒体禁止公共缓存，更新反代与 CDN 规则并清除旧 `/api/*` 缓存，不能让缓存命中绕过账户校验

## Meting 服务端授权

Meting 的 `/api`、`/test`、`/admin/openmusic`、`/admin/fm` 和 `/audio/qishui` 同时要求 API Token 和 OpenMusic 服务端短期签名

OpenMusic 在已验证的 HTTP 或 Socket 上下文中附带账户 ID，内部健康探测、房间漫游等受信任任务使用明确的 `system` 身份，不接受浏览器提交的账户 ID 作为授权依据

签名头为 `X-OpenMusic-Assertion` 和 `X-OpenMusic-Signature`，绑定版本、账户或系统身份、时间戳、随机 nonce、HTTP 方法、路径与查询参数、请求体摘要，允许时钟误差为 60 秒

- API Token 与签名均仅在服务端发送，浏览器不接收 Meting API Token
- 私有音乐账号只按服务端确认的房间上下文选择，忽略浏览器提交的房间选择参数，换绑或解绑账号后不复用之前凭据的私有响应缓存，缓存键仅使用凭据摘要
- 每次重试使用新 nonce，Meting 在当前进程内拒绝重复 nonce，缓存有容量上限，满时拒绝授权而不是删除有效记录
- Meting 多实例没有共享 nonce 存储，不能宣称已实现跨实例的全局防重放，部署时让同一上游使用单实例，或在扩容前接入共享重放存储
- 所有 Bearer 程序化入口统一校验短期断言，包括管理接口，不能借裸 Token 读取 Cookie 池或进入取链管理路径，管理员用户名与会话 Token 保留独立鉴权，注销必须先认证且仅注销已认证身份
- 签名使用管理后台维护的既有 Meting API Token，不新增手动编辑 `.env` 的运行时开关
- 如旧 Token 曾泄露，必须在 Meting 后台重新生成，并在 OpenMusic 后台同步更新，签名不能弥补服务端密钥泄露
- 两端应同步时钟，反代不得改变参与签名的目标路径与查询参数
- 搜索与歌单中的标准 Meting 地址改写为本站账户接口，仅保留必要参数，不向浏览器返回 Meting 主机名或附带的上游认证参数
- 汽水 OpenMusic 播放会话升级为 AES-256-GCM 加密的 v4，以账户 ID 作为附加认证数据，浏览器不能从凭据解码出上游地址，旧 v2/v3 会话失效，刷新页面后重新取链，旧临时 Redis 键自然过期而不迁移
- Meting 端口只绑定回环地址或容器私网，管理使用 SSH 隧道或独立受控管理入口，不得直接开放到公网，签名校验不等于网络隔离

## 拉黑替代曲

- 已通过账户令牌、Redis 会话和稳定身份校验的受限账户，调用 `GET /api/meting?type=url` 时不返回封禁错误
- 服务端丢弃原始音源、歌曲 ID、音质、Cookie、分页、重定向等参数，只向受信 Meting 请求 `server=netease&type=url&id=2094958154&quality=standard`
- 上游正常时返回 HTTP 200 与原有 `{ url, quality, ... }` 播放响应结构，不向客户端泄露内部处置原因，不返回原歌曲
- 替代曲不受普通音源开关影响，取链不附带被限制账户所在房间的私有音乐凭据，仍通过 OpenMusic 服务端短期断言调用 Meting
- 账户可登录、查看会话、bootstrap、刷新和注销，公开封面继续可读，房间、搜索、歌词、媒体代理、汽水源信息及 Socket 等其他业务仍拒绝，不能用替代策略取得其他业务权限
- 账户与 IP 额度、Redis 故障、凭据伪造和上游不可用不伪装为成功，分别保持 429、503、401 或上游失败语义，不能构造一个虚假的可播放 URL
- 统计中的拒绝量包含被人工限制的取链尝试，HTTP 指标将替代响应记为 `substituted`，不能把拒绝计数直接等同于 HTTP 错误数

## 媒体代理边界

- 汽水 CDN 仅精确或带点后缀匹配 `douyinpic.com`、`douyinvod.com`，包含品牌字符串的其他域名不能通过
- 已知 CDN 解析到私网、回环或保留地址时也拒绝，不因域名白名单而跳过 DNS 检查，使用 fake-IP DNS 的部署需让音乐 CDN 返回真实公网地址
- 媒体连接固定使用本次已验证的 DNS 地址，每次重定向重新校验并清除凭据，保持 TLS 验证，兼容 Range 与 gzip、deflate、br 压缩响应
- Meting JSON 响应默认最多 16 MiB，调用方仅可缩小上限，异常限流存储回复按不可用处理，不以空计数放行
- 微信代理只向上游发送必要协议头与过滤后的微信 Cookie，不透传本站账户 Cookie、管理员会话或 Authorization
- 仅透传受支持的音视频、常见位图与二进制媒体类型，HTML、脚本与 SVG 不通过，附加 `nosniff` 和沙箱响应头，避免同源可执行文档

## 管理后台

进入「账户风控」

1. 查看最近活跃或风险采样排序的账户，按正常、关注、限制访问筛选
2. 点击账户查看注册时间、已采集的注册 IP、最近登录 IP、累计请求、音乐与 Socket 请求、拒绝和错误响应
3. 查看今日播放取链、搜索、封面、歌词、汽水凭证等请求构成与最近 14 天的访问量
4. 查看最近成功登录、历史登录 IP 与同 IP 的关联账户，关联只表示共享网络线索，不表示同一人
5. 添加最多 10 个标签，每个最多 24 字，填写内部备注与必填处置原因，再确认保存
6. 「限制访问」阻止该账户所有会话的普通业务和 Socket 请求，并断开本进程的账户连接，保留登录态且音乐取链返回指定替代曲，正常、关注和受限状态均不豁免额度
7. 「安全事件」显示登录失败摘要与额度、封禁事件，重复额度告警按账户每分钟合并
8. 「请求额度」调整全局阈值，保存至 Redis 并对新请求即时生效

所有风控详情仅向后台管理员开放，修改同时沿用后台来源校验、初始安全设置门禁和操作审计，不向普通房间成员广播 IP、标签或内部备注

跨进程 HTTP 与入站 Socket 事件使用相同 Redis 状态，其他进程已建立的空闲连接不保证被即时主动断开，其下一次事件会被拒绝，不能将该机制描述为全局实时踢线

## 默认额度与计数

| 范围 | 默认额度 |
| --- | --- |
| 单账户每分钟业务总请求 | 600 |
| 单账户每日业务总请求 | 30000 |
| 单账户每分钟音乐请求 | 120 |
| 单账户每日音乐请求 | 5000 |
| 同 IP 每分钟业务总请求 | 3000 |

计数包含业务 HTTP 请求、有效凭证的刷新尝试和 Socket 事件，不包含静态资源、登录状态轮询、引擎心跳和内部定时任务，音乐缓存命中也计数，已拒绝的请求计入拒绝数与尝试量

扫码、队列、漫游等可能触发上游调用的 Socket 事件同时消耗音乐额度，房间后台定时任务不计入某个浏览器的入站请求额度

额度通过 Redis Lua 原子更新，重复提交、多标签页和多实例不能把同一账户的额度拆开，固定分钟窗口允许边界附近的短时突发，不是平滑令牌桶

IP 必须来自现有可信代理解析链路，勿直接信任客户端的 X-Forwarded-For，校园网、企业网、NAT 和移动网络需要适当提高共享 IP 额度

## 风险评分

账户详情的「请求与配额」增加按 IP 分组，分别记录总请求、歌曲请求、WebSocket、封面与其他接口次数
每次已认证歌曲或 WebSocket 请求进入 Redis 原子记录链路，包括被拒绝的尝试，歌曲类 Socket 同时归入歌曲列和 Socket 列，总请求只增加一次
重要请求明细保留近 24 小时最近 200 条，分组保留近 90 天最近活跃的 200 个 IP，各列是该分组保留期间的累计值，不补造升级前明细

歌曲 IP 切换按同一账户连续歌曲请求计算，使用服务端可信代理解析后的地址，图片或普通页面刷新不影响该窗口
10 分钟窗口按时间自然衰减，至少 3 个歌曲请求 IP 才启用频繁切换因子，两个固定出口间切换不命中
无法仅靠 IP 判断是否属于公司网络，分值仅供人工复核，不自动封禁，正常共享出口本身不加分

新增 Redis 键均位于 `openmusic:risk:v1:` 下：`music-ips:<账户>`、`music-ip-changes:<账户>` 保留 20 分钟并仅按最近 10 分钟计算，最多各 500 项；`request-ips:<账户>` 与 `request-ip-counts:<账户>` 保留 90 天并限制最近 200 个 IP；`request-events:<账户>` 保留 24 小时且最多 200 条
旧数据缺少这些键时按空集合读取，后续请求幂等更新分组、原子追加明细，无需批量迁移或清空 Redis
发布时先升级服务端，再升级 Web；回滚保留新增键，旧版本忽略新字段，旧版共享 IP 评分和封面登录要求会恢复，需重新核对后台提示与首页图片

| 信号 | 分值 |
| --- | --- |
| 当日拒绝达到 10 次 / 100 次 | 30 / 50 |
| 近 24 小时访问 IP 达到 5 个 / 10 个 | 20 / 30 |
| 当日分钟请求峰值达到 600 | 30 |
| 最近活动 IP 在近 90 天关联至少 5 个账户 | 0，仅展示关联，不能据此判断公司或校园共享出口违规 |
| 近 10 分钟歌曲请求使用至少 3 个 IP，切换达到 6 次 / 12 次 | 20 / 30 |
| 当日账户凭据验证失败达到 10 次 / 50 次 | 15 / 25 |
| 近 24 小时客户端声明特征达到 5 项 | 10 |
| 当日进入至少 10 个不同房间且入房达到 30 次 | 15 |
| 当日错误达到 20 次且错误比例至少 30% | 15 |
| 当日请求达到 1000 次且音乐请求占比超过 90% | 10 |

分数最高 100，低于 30 为低风险，30 至 59 为待关注，60 起为高风险，管理员可看到每项原因

风险分数不会自动封禁，共享 IP 单项不能判为高风险，凭据失败也可能表示账户正受到攻击，客户端声明可伪造，不等同于设备硬件指纹，未绑定邮箱或某种第三方登录方式不会直接加分

列表默认按风险采样降序，状态筛选和分页保留该顺序，队列分值使用排序视图的同一快照，登录、请求、错误、认证失败和成功入房会更新采样，30 秒自动刷新只读取新数据，不执行全量重新评分，详情按当前数据复核，过夜未活跃账户的采样可能过时

## 后台画像与操作

- 身份与风险：账户名称、完整绑定邮箱及验证状态、是否设置密码、房间身份、绑定平台账号名称、脱敏标识、绑定时间、注册时间和注册 IP，以及逐项风险依据
- 房间与昵称：成功进入过的房间 ID 和当时名称、最近入房昵称、首次与最近进入时间、次数、只读方式、可信 IP、历史昵称，不读取或展示私密房间口令
- 请求与配额：今日操作分布、全局额度、最近 14 天有活动的日期、账户错误分类与最近明细，统计包含被拒绝的已认证尝试，不将请求次数描述为业务成功次数
- 默认每日音乐请求 10000、每日总请求 50000，分钟额度不变，已经在后台保存的额度保持原值，需要调整时在后台保存
- 错误分析保持既有已认证业务 HTTP 错误口径，按安全原因码、状态码、接口操作、方法和音源分组，展示累计、今日、首次与最近发生时间，门禁拒绝与凭据失败仍独立统计
- 旧错误总数不清零，升级前没有明细的错误显示为历史未分类，无法从旧计数还原具体原因，新增分类不会把上游或配置故障自动判定为用户违规
- 登录与网络：成功登录、历史登录 IP、最新登录或请求 IP 的关联账户、客户端声明，统一使用北京时间，不使用浏览器所在时区
- 标记与处置：状态、最多 10 个标签、内部备注、必填处置原因及二次确认，近 90 天处置历史可见，具体操作者通过既有管理审计日志核对
- 支持完整账户 ID、邮箱和历史 IP 精确检索，也支持名称、近 90 天昵称、绑定账号名称、登录平台、房间身份 ID、邮箱片段与标签的文字匹配，不区分英文大小写，不执行正则或通配符
- 文字检索使用排序快照，每批最多读取 100 个账户，最多扫描 50000 个候选且设置 5 秒检查预算，超限明确提示改用精确检索，不返回部分结果，概况中高风险与限制访问数量为全站范围，匹配数量为当前筛选范围
- 加载失败通过顶部消息提示并清空旧列表，避免将旧数据误认为新的搜索结果，连续自动刷新失败合并提示，手动搜索或刷新可重试

本次不改变普通用户操作步骤，`client/src/lib/userGuide.ts` 无需新增后台风控指引

## 数据模型与保留

新增 Redis 命名空间为 `openmusic:risk:v1:`，不修改既有账户、收藏、房间、凭据键的格式

- 账户档案、注册 IP、最近登录和访问 IP、累计量、人工标签和处置长期保留，需要纳入站点的账户数据删除与备份管理流程
- 登录明细最多 100 条且不超过 90 天，登录 IP 最多 100 个且不超过 90 天，近 24 小时访问 IP 单独统计，最多 500 个
- 同 IP 关联账户最多 2000 个，最多 90 天，达到上限时属于截断线索，不是完整账户关系图
- 每日计数保留约 35 天，后台展示最近 14 天，分钟计数 120 秒后过期
- 新增 `error-groups:<账户>`、`error-meta:<账户>`、`error-events:<账户>`，累计分类最多 100 组，超出归入其他错误而不丢计数，最近错误最多 100 条且不超过 90 天，分类计数和累计错误原子写入，详情从同一事务读取错误快照
- 错误只保存白名单原因与固定操作标识，不保存原始异常、堆栈、完整请求地址、查询参数、请求体或凭据，旧客户端可忽略新增字段，回滚旧版本后新增分类键保留，错误总数仍沿用原字段
- `day-cn:<账户>:<日期>` 和 `room-day:<账户>:<日期>` 按北京时间自然日分桶，HTTP 错误按请求开始时间归属，跨零点响应不污染新一天错误率
- 房间历史与名称明细最多 200 个、客户端特征最多 50 项、历史昵称最多 20 项，均不超过 90 天，房间日索引保留 2 天，同账户同房间 60 秒内合并入房次数
- 处置历史最多 100 条且不超过 90 天，原账户当前状态、标签、备注不受历史过期影响
- 全局安全事件最多 2000 条且不超过 90 天，后台最多展示最近 200 条，不能把它描述为完整请求日志
- 不额外保存密码、Cookie、Token、完整请求体、音乐服务凭证，身份画像只从现有账户记录选取安全字段，登录与请求共用清理和截断至 320 字符的客户端声明
- 旧账户在后续登录或访问时纳入风控，升级前没有采集的注册 IP 和历史登录 IP 不会虚构补写
- 旧状态索引按账户索引分批幂等补齐，每次查询最多处理 100 批，每批提示数量 200，未完成时返回 `503 RISK_INDEX_BUILDING`，后续查询继续，不将未整理完整的数据当作最终筛选结果
- 初始化和后续写入幂等，房间、昵称和客户端历史仅从升级后开始采集，采集失败记录 `risk_storage_error_total`，不会撤回已成功完成的入房操作
- 当前实现使用单 Redis 实例语义，不支持 Redis Cluster 跨 slot 脚本

## 北京时间日统计切换

- 首次启用记录切换日，旧 `day:<账户>:<UTC 日期>` 键原样保留，不覆盖旧数据
- 仅在切换日，账户第一次触发采集时将与当天相交的两个旧 UTC 日桶保守求和，分钟峰值取最大，标记一次后不重复导入，旧数据可能包含相邻北京时间日活动，后台显示“升级日保守估算”
- 下一北京时间自然日起只写入新的日桶，旧统计在详情独立折叠显示，显示区间换算为北京时间但不伪装成新自然日
- 先更新服务端再更新客户端，切换窗口需停止旧服务端实例，不能长期新旧日统计版本混跑，实例共用 Redis 与一致时钟
- 回退只恢复程序版本，保留旧日桶和新增键，旧版本不会读取新桶，回退当日旧额度可能落后于升级期间活动，需临时收紧额度并在下一个日界线后复核，不能将回滚描述为无损合并

## 发布与回滚

1. 发布负责人先备份当前部署版本与 Redis，确认至少一种普通用户登录方式已经可用，检查 SMTP 或 OAuth 的实际回调
2. 先发布新版 OpenMusic 服务端，验证原有 Meting 仍能接收附加签名，新版服务端已要求业务访问登录
3. 发布新版 Web 客户端，确认邮箱、已启用 OAuth、微信文件传输助手首登与绑定、注销、跨标签页和 WebView 登录流程
4. 再发布新版 Meting，裸请求与仅 Bearer 请求应为 401，经已登录 OpenMusic 发起的音乐请求应正常
5. 反代禁用 API 公共缓存，运行 `nginx -t` 后 reload，清除 CDN 旧 API 缓存，必要时从后台轮换历史泄露的 Token
6. 验收匿名 API、匿名 Socket、正常搜索播放、汽水取链、超额 429、人工限制、解除限制与 Redis 中断时的 503
7. 观察 `account_request_total`、`account_access_rejected_total`、`account_socket_rejected_total`、`risk_storage_error_total` 及原有上游失败量，这些进程内计数和日志不是独立告警平台

此变更需要重启 OpenMusic 和 Meting，不改端口、卷或启动顺序，依赖已有 Redis 持久化，移动端桥接字段不变，但旧网页资源必须刷新，不要通过清理本站 Cookie 或存储数据来更新资源，否则可能失去游客迁移依据

账户令牌升级必须配套发布新版 OpenMusic 服务端与 Web 客户端，旧客户端不会刷新三天访问令牌，发布前确认已备份加密主密钥与 Redis，新版匿名请求和仅持有旧共享 key 的请求必须返回 401，验收访问到期、无感刷新、30 天绝对到期、重放撤销、注销和 Redis 故障恢复

账户令牌相关回滚只恢复配套程序版本，不删除 `openmusic:account:auth:v2:` 密钥或会话数据，不重新生成已有密钥，回退到旧版本会恢复旧会话策略，必须另行评估其安全影响

若正常账户出现大面积 401、503 或播放失败，先检查 Token 一致性、时钟、反代路径、Redis 与登录配置，再决定回退

回滚必须匹配两端版本，不能在新版 Meting 保持强制签名时单独回退 OpenMusic 到不签名版本，不删除新增风控键，不轮换已有房间和身份密钥，回退旧 OpenMusic 会恢复旧版本匿名行为，需在边缘临时限制业务入口

发布记录应由负责人填写实际版本、发布时间、验收结果、回滚触发条件与负责人，不以本文代替生产验收

## 账户昵称

昵称保存在既有 `openmusic:account:<accountId>` 记录的可选 `nickname` 字段中，使用比较并交换避免并发更新覆盖登录方式、密码或稳定房间身份，不新增键或批量迁移

登录和会话响应追加 `account.nickname`，旧记录缺少字段时兼容为空，首次登录可从当前设备尚未归属其他账户的旧昵称缓存补齐，已保存的账户昵称优先，进房也可从该账户对应的既有房间昵称补齐

`POST /api/auth/nickname` 只使用服务端会话中的账户 ID，支持 `nickname` 和仅补齐空昵称的 `initializeOnly`，不接受目标账户 ID，经过现有身份、权限与风控中间件，并按账户限制每分钟最多 20 次，未认证返回 401、无效昵称返回 400、过频返回 429、存储失败不返回保存成功

进房与重连以账户昵称为准，房间内改名先保存账户再更新房间展示，昵称按现有规则限制为 20 个字素，房间重名追加数字仅影响房间展示，不改写账户昵称，风险控制昵称历史仍为审计数据

部署时先升级服务端、再升级客户端，无环境变量或迁移操作，回滚可保留可选字段，旧版本会忽略该字段并恢复本地缓存行为，生产验收需覆盖重新登录、换设备、账户切换与 Redis 故障

## 账户音乐会员与房间生命周期

登录账户后，扫码绑定成功必须先将会员凭证加密写入既有 Redis 哈希 `openmusic:account:music:<accountId>`，再更新房间并确认成功，写入失败返回 `ACCOUNT_MUSIC_SAVE_FAILED`，不以当前房间临时可用代替账户持久化成功

创建或复用空房间时以服务端房间归属恢复账户音乐会员，返回恢复后的新快照，恢复失败返回 HTTP 503 和 `ACCOUNT_MUSIC_RESTORE_FAILED`，房间可能已创建，重试创建可复用已有空房间继续恢复，不会因创建冷却阻止这次重试

登录迁移、主动认领旧房间、房主刷新音源账号和新建房间时，按服务端确认的归属补存仍存在的旧房间音乐凭证，使用 `HSETNX` 仅补齐缺失平台，不覆盖账户已有会员或共享状态，无法从已销毁且从未备份的房间找回私有凭证

账户删除会员后，该平台字段保留不含凭证的 `{ deleted: true, updatedAt }` 标记，旧房间补存不复活删除记录，主动重新扫码可覆盖标记，旧版本读取会忽略无元数据的标记，无新增键、TTL 或批量迁移；旧版本若再次删除该字段，回到新版后仍需重新确认删除以建立保护

新房间中的会员使用新房间的私有标识，不继承全站共享开关或共享撤销凭据，账户列表、保存与共享响应均不返回撤销凭据，房间点歌与聊天规则的本机缓存不等同于账户会员持久化

开启匿名登录时继续复用原有 HttpOnly 设备 Cookie 身份和房间扫码、绑定、列表、解绑接口，服务端以既有算法从已核验的身份派生 `acct_anon_<hash>`，在同一 `openmusic:account:music:<principalId>` 哈希中加密缓存会员，与正式账户隔离，不创建正式账户或写入正式账户房间索引，不新增浏览器 Cookie 字段，也不向浏览器下发音源 Cookie

同一匿名身份创建或复用空房间会恢复私有会员，清除设备 Cookie 或换设备无法自动领取原缓存，关闭匿名登录后 HTTP 业务请求和后续 Socket 事件拒绝匿名读取；绑定与恢复失败分别返回 `MUSIC_COOKIE_CACHE_SAVE_FAILED` 和 HTTP 503 `MUSIC_COOKIE_CACHE_RESTORE_FAILED`，失败后可以重试创建，匿名解绑同时写入平台删除标记，旧房间不能重新补存该平台

登录正式账户时仅迁移服务端核验的旧设备身份缓存，重新按正式账户作用域加密并通过 `HSETNX` 填补缺失平台，不覆盖正式账户已有会员或删除标记，保留源缓存，不改变既有键结构或 TTL，无需批量迁移，已经解散且从未缓存的房间仍需重新扫码

先升级并重启服务端，再升级网页资源，保留 Redis 和现有凭证加密密钥，观测 `account_music_save_total`、`account_music_restore_total` 的成功与失败计数及稳定错误码，这些计数不是完整监控告警；回滚保留账户哈希与删除标记，但旧版仍存在静默失败与恢复前快照问题

## 单账户风险重置

账户画像「标记与处置」页提供「重置风险状态和分数」，需要填写 1 至 200 字原因并经管理员确认

- 服务端原子将账户状态恢复为 `normal`，风险分数和排序分数置为 0，并移出限制账户池
- 保留账户累计统计、历史明细和处置审计，重置后的下一次登录或请求会重新开始评分
- 账户存在多个 IP 时，从近 90 天账户 IP 活动中保留最近使用的 IP，写回最近网络与请求来源字段，不把旧 IP 覆盖为当前 IP
- 同时清除待处理的人机验证轮次，不能绕过请求额度和后续重新计算的风控规则

接口为 `POST /api/admin/risk/accounts/:id/reset`，请求体必须包含 `reason`，复用管理员会话、Origin 和初始化完成校验，账户不存在返回 404，原因无效返回 400，结果和操作者写入管理审计

此操作只在后台出现，主站新人指引 `client/src/lib/userGuide.ts` 无需新增步骤

## 清除风控历史

管理后台「账户风控」页面右上角提供「清除历史数据」按钮，确认弹窗会展示全站清理范围，取消不会发起清理请求

- 清除历史 IP、登录记录、客户端特征、歌曲与 Socket 请求明细、按 IP 分组统计、入房与昵称历史、错误分类与明细、往日统计及清理开始前的安全事件
- 保留账户资料、登录会话、人工限制与处置历史、标签备注、风控策略、今日统计、分钟和当日额度，今日入房与拒绝等风险因子仍可能生效
- 为防止升级日重复导入，今日迁移标记和仍与今日相交的旧 UTC 兼容统计桶一并保留
- 账户累计计数以保留的今日统计为新起点，历史 IP 和请求明细在后续活动中重新采集，清理不会修改绑定到账户的正式昵称
- 清理按批次执行，每个账户的历史和累计计数在 Redis 中原子更新，正常访问不暂停，清理期间和之后可能出现新记录，不能将完成后的页面理解为空站快照

接口为 `POST /api/admin/risk/history/clear`，请求体必须包含 `confirm: "CLEAR_RISK_HISTORY"`，复用管理员会话、Origin 和初始化完成校验，缺少确认返回 400，重复清理返回 409，存储不可用或中途失败返回 503，不会返回成功

多实例通过 Redis 锁避免同时清理，锁在每批及每次删除时续期，异常退出后最多五分钟释放，失败可能已经清除了部分记录，可恢复 Redis 后重试，成功与失败均写入独立管理审计，管理审计不属于清理范围

不新增配置、环境变量或迁移，先升级服务端再升级客户端，需要重启服务端，管理员确认前应按需要备份 Redis，程序回滚不能恢复已经删除的历史，只能从事先备份恢复，账户及现有额度不需要迁移

此操作只在后台出现，主站新人指引 `client/src/lib/userGuide.ts` 无需新增步骤

## Redis 热路径与查询保护

- 消费计数脚本优先使用固定 SHA 的 `EVALSHA`，仅收到 `NOSCRIPT` 时用 `EVAL` 重建脚本缓存，连接故障和权限错误不重放非幂等计数，Redis ACL 需允许既有 `EVAL` 和新增使用的 `EVALSHA`
- 风险评分将当日计数与已分类操作通过一次固定字段 `HMGET` 读取，不在请求热路径增加 `SCAN`、`KEYS`、全站查询或历史事件遍历
- 无筛选风险列表与最近活动列表直接分页读取持久索引，不再为每次默认轮询复制全站集合
- 完整账户 ID、完整邮箱和 IP 精确查询仅按候选账户读取评分和状态，不先复制全站集合，状态筛选直接求对应索引交集
- 模糊搜索仍需要候选快照及分批读取，建立快照前检查账户范围，超过 50000 个账户要求改用精确查询，保留原有五秒搜索预算，不能将该能力描述为适合无限账户量的全文检索
- 错误分组及分类元数据补充 90 天滑动 TTL，错误列表保持最多 100 条，过期分组不再展示，累计错误数仍保留，不通过删除累计值掩盖错误
- 既有最近重要请求最多 200 条、请求 IP 分组最多 200 项、客户端特征最多 50 项等上限保持不变，新增因子只复用固定操作字段，日桶继续按原 TTL 清理

首次读取列表使用 `status-index:v5` 和 `status-index:cursor:v5` 分批幂等整理状态与评分索引，仅为缺少评分的旧账户补充 0 分，不覆盖已有采样分或人工处置，完成标记持久保留，处理中断后可从游标继续，达到本次批次预算返回 `RISK_INDEX_BUILDING`，稍后重试，不使用进程内数据替代 Redis 权威状态

这些措施降低单次请求与默认轮询的放大，但账户档案、全站账户索引等仍随账户生命周期增长，不承诺 Redis 永不耗尽，生产容量需按账户数、并发、留存及实际配置评估，观测 Redis 内存、命令延迟、拒绝写入、客户端连接数和既有风控存储错误指标，本文不代表已部署监控告警

上线先升级服务端并重启，再发布客户端，无新增环境变量和人工数据迁移，发布前检查脚本 ACL，保留旧索引与新增兼容标记，回滚程序无需删键或重置当日额度，新增 TTL 会使长期不活跃的错误分类到期，回滚程序不能恢复已过期的分类详情，必要时从事前 Redis 备份恢复

## 风控池与替代曲隔离

账户状态为 `blocked` 的记录进入独立风控池，默认主列表只读取主索引，不再展示已限制账户，后台通过「账户池 → 风控池 · 已限制账户」查看和处置，完整账户 ID、邮箱或 IP 搜索在主列表中不会绕过该隔离，必须明确进入风控池或全量账户池

主列表与风控池使用独立的 Redis 有序索引，风控账户不会通过默认轮询临时复制后再过滤，状态变更在同一 Redis Lua 操作中同步移入或移出两个索引，解除限制后回到主列表，旧账户索引由 `status-index:v5` 分批幂等整理，初始化期间返回 `RISK_INDEX_BUILDING`，不使用进程内列表替代 Redis 权威状态

风控后的 URL 请求可能返回固定替代曲，响应摘要会标记为 `substituted`，这类响应不进入目标歌曲重复统计、目标歌曲数和重复率分母，失败、空结果和中断也不进入重复目标统计，避免把风控策略自身造成的固定返回误判成刷歌行为

## 歌曲请求的响应摘要

HTTP 音乐请求现在通过服务端生成的随机请求 ID 关联请求与最终响应，画像概览展示今日正常、空结果、失败、中断、替代曲、平均完成耗时及采样目标分布，请求页展示实际返回的歌曲 ID、名称、歌手与音源，响应状态和耗时，以及搜索或歌单的返回条目数

- 仅从实际 JSON 响应提取歌曲元数据，每次最多取前三项，并截断名称、歌手和 ID，已知容器最多展开两层，不遍历完整歌单，不为审计额外请求歌曲详情或调用上游
- 取链或歌词响应没有歌曲元数据时，只记录经校验的请求歌曲 ID，并明确显示响应未含歌曲元数据，不将请求参数冒充响应确认的歌曲身份
- 不保存播放 URL、歌词正文、音频内容、解密密钥、Cookie、Token、搜索词、歌单原始 URL 或任意响应正文，正常客户端仍收到未被改写的原始响应
- `HTTP 200` 中的空数组、空取链或空歌词会标记为空结果，业务错误、HTTP 错误、受限账户替代曲和连接中断单独标记，HTTP 正常只代表服务端请求完成，不证明歌曲已播放或可播放
- 额外新增的重复目标、目标歌曲数和响应结果分布为人工复核因子，不直接加风险分，避免把循环播放、歌词刷新及失败重试误判为滥用，重复目标分母仅含正常的取链、歌词和歌曲信息响应，不含搜索、歌单、失败及替代曲
- 当前只采集明确支持的 HTTP 歌曲接口，Socket 仍保留既有请求记录，不将客户端提交的队列歌曲名当作真实上游响应，不改变 Web、Flutter 或 Android 的事件和桥接字段

新增 Redis 键为既有风控前缀下的 `music-response-order:<accountId>` 列表和 `music-responses:<accountId>` 哈希，每账户最多保留 200 条最近完成摘要，两个键均为 24 小时滑动 TTL，读取时再次过滤请求发生时间超出 24 小时的记录，现有请求明细与响应留存独立，慢请求完成后可能只在响应列表中出现

每次被采集请求完成后仅增加一次固定规模 Lua 写入，优先使用 `EVALSHA`，仅 `NOSCRIPT` 时重建缓存，无热路径扫描、全量 JSON 存储和补查上游，去重、插入和旧记录淘汰原子执行，在当前保留窗口内重复完成通知不重复累计，网络错误不重放，异常仅记录既有 `risk_storage_error_total{operation=music_response}` 指标，不阻塞或伪造客户端的业务响应

日统计复用既有北京时间日桶，字段为 `response_total`、`response_ok`、`response_empty`、`response_failed`、`response_substituted`、`response_aborted` 和 `response_duration_ms`，按请求开始时间归属自然日，日桶 TTL 沿用 35 天，仅包含升级后成功记录的响应，不补造历史或将不存在的记录当作完整监控，服务端异常退出、存储写入失败等可能造成采集缺口

清除风控历史同时清理两个新增摘要键，保留今日响应统计，无需人工迁移或新增配置，先升级服务端再升级客户端，回滚时旧程序忽略可选响应字段，新增键会自行到期，已经删除或过期的摘要只能通过事前备份恢复，已评估主站新人指引，无需为后台采集新增主站步骤

### Cookie 复制的防护边界

有效 Cookie 是持有者凭据，复制到第三方客户端并不是 Cookie 解析器注入，不能靠 User-Agent、Origin 或客户端内置签名可靠地区分合法浏览器与伪装客户端

异常访问闸门能限制持有有效 Cookie 的异常抓取，现有刷新轮换、旧值重放检测及绝对期限仍保留，但不能承诺阻止真人分享当前有效凭据，或真人验证后在规则允许范围内继续调用

不要公开分发带本站凭据的 APK，不要把 Cookie、refresh token 或 OAuth secret 写入日志、链接、前端配置或构建产物

## OAuth 失败诊断

两家回调原先将多个阶段统一映射成 `error`，单凭 `?linuxdo=error` 或 `?github=error` 无法判断接入地址、密钥、网络还是会话保存出了问题

现在服务端使用 `OAuth callback failed` 记录脱敏 provider、stage、code 和可用的 upstreamStatus，不记录授权码、state、Cookie、token、完整 URL 或上游响应正文，浏览器仍显示原有通用错误

- `configuration`：配置不完整，核对后台保存的 Client ID、回调地址及密钥已配置状态
- `state_signature`：state 签名无效或过期，核对跳转是否超时、发布期间主密钥是否变化、多实例是否使用同一个稳定 `CLIENT_ID_SECRET`
- `state_binding`：浏览器挑战 Cookie 缺失、Redis 挑战过期或已消费，核对起始站点与回调域名是否一致、HTTPS、Cookie 路径和 Redis 共享情况
- `token`：令牌交换失败，按脱敏网络错误码或 HTTP 状态检查服务器出网、TLS、Client Secret、回调登记是否完全一致，不关闭证书校验
- `profile`：用户信息请求或返回数据解析失败
- `account_session`：上游身份已取得，但账户绑定、会话记录或身份同步失败，需继续核对服务端 Redis 和稳定密钥，不应直接要求用户重建 OAuth 应用

现有诊断不等于已经验证线上 Linux.do/GitHub 登录成功，需要在实际部署环境完成一次授权并结合脱敏日志定位


### 2026-10-28 续查补漏
